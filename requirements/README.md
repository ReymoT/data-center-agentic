# Candidate environment

These are the sole maintained copies of package 1.0's proposed core input and Windows x64 CPython 3.12 lock. The lock was dependency-resolved before this task; runtime validation in this branch must be reported separately in [the handoff](../docs/handoffs/F01.md). [Q09](../docs/decisions/Q09_OLLAMA_QWEN3.md) now accepts Ollama/Qwen3 8B with temperature 0.2; Matty owns SDK compatibility/version-lock preparation. No provider SDK has been added to this lock yet. Deployment pins/resources remain pending; supported platforms and Python adoption remain Q13. Do not claim this is the final environment.

Create an isolated Python 3.12 environment, install using `--require-hashes`, run `pip check`, `scripts/smoke_dependencies.py`, Ruff check/format, then the offline bootstrap validator as shown in [README](../README.md). Package installation requires network access; smoke execution itself is offline and uses no model.

The smoke script verifies all direct imports, a SHACL validation and SPARQL query, a certified tiny integer program, both classifier save/load predictions, and a bounded LangGraph route. These verify dependencies, not the project algorithms or safety.

Ordinary PR/main CI validates instruction/configuration records, installs the hashed Windows candidate, checks dependencies, runs offline smoke operations, executes `python -m pytest tests -q` and checks lint/format/compilation. This includes existing F02 contracts, D01 source inspection and provider helpers, with new offline tests discovered as implementations arrive. Installation contacts the package index; checks use synthetic test fixtures and no external dataset or model service. [The current handoff](../docs/handoffs/F03_F04_F05_MAINTENANCE.md) records a clean-install verification and its limits. A Windows dependency-lock check must not be silently copied to Linux/macOS. Regenerate each accepted lock from the reviewed input after provider/stack changes; retain resolved hashes and validate imports and consumer behavior.

Troubleshooting: confirm 64-bit CPython 3.12 and matching wheel target. On hash failure stop and verify the input/lock; do not disable hashes. On unavailable pinned versions, record evidence and review a replacement rather than substituting versions. On missing pip/venv support use an actual full Python installation or a packaged pip installer that targets the isolated environment. Do not edit global Python packages. If a sandbox denies temporary-file creation, set TEMP and TMP to an existing writable local directory for that process and retry the actual checks; do not remove tests. Missing provider settings block live calls, not offline checks.
