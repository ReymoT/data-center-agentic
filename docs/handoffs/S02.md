## API and scope

The explicit development adapter is `dc_sustainability.simulator.impact`:

```python
from dc_sustainability.simulator.impact import account_realized, compare_realized

raw = sim.result(run_id="RUN-S02", system="greedy_a")  # after all 30 steps
accounting = account_realized(private_episode, raw)
result = accounting.result
completed_it_kwh = accounting.completed_it_energy_kwh
# With two runs on matching episode inputs:
comparison = compare_realized(baseline_accounting, accounting)
```

Existing S01 result/state/step behavior is unchanged. This API accepts trusted S01
output; it is not an independent validator and cannot authenticate execution from
an arbitrary supplied result. E01 retains independent arithmetic.

Exact P01 interface: `calculate_impact(schedule_id: str, input_id: str,
horizon: Horizon, site: Site, work: Iterable[Work], placements: Iterable[Placement],
completed_job_ids: Iterable[str], carbon_g_per_kwh: Mapping[int, float]) -> Impact`.
`compare(baseline: Impact, candidate: Impact) -> Savings | Blocked` performs the
shared input/horizon/completion/carbon guards. `display1(float) -> str` supplies
P01 display rounding, though this adapter returns unrounded values.

This adapter follows Edison's October 23 proposal in
[Issue #36](https://github.com/ReymoT/data-center-agentic/issues/36#issuecomment-6372863356):
`Site(background_kw, pue, slot_hours)` from F02; `Work(job_id, power_kw,
duration_slots)` for every episode job; `Placement(job_id, start_slot)` from
recorded executed starts only; `Horizon(0, 30)`; completion IDs from S01; private
realized g/kWh observations mapped by slot. Duplicate observations for a slot
raise an ambiguity error rather than select one. Missing observations stay absent.

`Impact` contains immutable `SlotImpact` rows and `Totals`. Its six totals supply
existing `EpisodeTotals`; slot energy/emissions supply existing `SlotRecord`
fields. Job/background/site energy is facility kWh including PUE. Completed IDs
and local completed IT kWh are separate: completed IT work is the sum of completed
jobs' power × duration × slot hours, excluding PUE, background and unfinished jobs.
`EpisodeResult.completed_work` stays None as directed in #24.

The local `RealizedAccounting` wrapper is not an F02 schema or policy view.
Forecast estimates have no input path into it: forecasts remain in S01's separately
supplied visible forecasts. No forecast estimator, fallback, carbon imputation or
source-semantic default is implemented. Missing carbon keeps known energy but
leaves affected emissions None.

`compare_realized` delegates arithmetic and comparability to P01, additionally
refusing savings for any unfinished episode jobs, including never-started jobs
that P01's placed-job leftover set does not cover. Consumers must use this wrapper
for S02 savings; subtracting raw totals does not establish a savings claim.
