## Delivered consumer validation

[The new consumer suite](../../tests/verification/test_d03_consumer.py) calls the
actual D03 generator and production checker, without replacing either with mocks.
It exercises all four scenarios using explicit development-only seed 42. This seed
is a test input, not Q06 agreement or the selected experiment seed.

The 29 cases cover every generated job's arrival-time start, intentional impossible
deadlines, nonflexible delays, backdated starts, duplicate starts after validation
bypass, unknown future jobs and hidden job-specific constraints, exact/one-kW-below
capacity boundaries before PUE, missing capacity and the J1/J2/J3 hand fixture.
No job record is rewritten to force a passing answer. Capacity tests deliberately
change an explicit authoritative synthetic constraint and check the actual verdict.

The suite's constraint/view helpers are test fixtures, not a second production
adapter or S01 implementation. They use public Job fields and F02's existing
visibility helpers. Private split/seed/scenario metadata and future-job constraints
are absent from the tested policy-facing view. Real simulator visibility, state
progression and runtime integration still need S01 acceptance.

Otherwise feasible proposals still return an unresolved-rule error and cannot be
converted to ApprovedActions. Impossible starts produce actual violations. Missing
carbon does not support emissions/savings claims. No fresh/stale forecast rule,
coverage/deferral rule, aggregate infeasibility objective or completion-start policy
was invented. The production checker is unchanged; no mock or constant approval is added.
